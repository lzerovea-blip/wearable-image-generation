# 四能力生成工作流

本文件用于执行文生图、图生图、文生动图、图生动图。所有 App 和穿戴界面都必须使用 HarmonyOS Sans / 鸿蒙字体。

执行产物、目录、失败处理和动画验收细则见 `references/execution-and-output.md`。除非用户明确只要提示词，默认都要生成并保存可检查文件。所有图片生成、图片改写和动画关键帧生成必须使用 `imagegen`。

## 共享提示词结构

每次生成或改写提示词时，至少覆盖这些字段：

- 能力类型：文生图、图生图、文生动图或图生动图。
- 目标载体：手机 App、圆形穿戴屏、方形穿戴屏、图标、组件、完整页面或短动图。
- 穿戴形态默认值：凡需求涉及穿戴设备、手表、watch 或 wearable，且未明确出现“方表 / 方形屏 / 方形穿戴 / Watch Fit / rectangular watch / square watch”等方形设备信号，目标载体默认写为圆表、圆形屏。
- 用户目标：这个界面或动图要帮助用户理解什么、完成什么。
- 健康/运动场景：健康总览、运动训练、睡眠、心率、血氧、压力、设备同步、告警、设置、报告等。
- 功能原型：最接近需求的整屏截图、页面类型、组件组合或组件索引条目。
- 设计规范：手机运动健康 App 规范或智能穿戴规范。
- 组件资源：导航、卡片、列表、图表、按钮、弹窗、开关、选择器、状态提示等。
- 数据表达：指标、单位、数值、趋势、范围、状态、告警语义。
- 页面类型锁定：动画任务所有帧必须保持同一页面类型，只允许指定运动元素变化。
- 保留/修改：图生图和图生动图必须明确保留项与修改项。
- 输入身份锁定：图生图和图生动图默认锁定输入图画幅比例、裁片边界、组件形态、可见元素、点数、焦点尺寸和边缘关系。
- 裁片保真：参考图只露出卡片上缘或局部内容时，输出必须保持同等裁片关系；不得补全被裁掉的卡片下半部，不得为了展示新内容改变裁片内的信息密度。
- 小组件几何锁定：竖向 Swiper、导航点、局部控件裁片等必须锁定点数、点半径、点距、主焦点尺寸、弧边关系和组件尺度；动图只移动或替换蓝色焦点状态。此类任务优先使用确定性脚本从原图复制帧，不让 `imagegen` 重新生成大尺寸组件。
- 系统壳层：手机 App 禁止 iOS 状态栏、电量样式和 home indicator；使用 HarmonyOS 风格系统壳层，或弱化系统壳层。
- 负面约束：不要文字裁切、不要微小不可读文字、不要设备形态变形、不要随机品牌标识、不要组件混乱、不要过度装饰、不要伪称官方。

每次产物任务还必须记录：

- 输出目录：`outputs/<YYYYMMDD-HHMMSS>-<ability>-<slug>/`
- 静态产物：`final.png`
- 动画产物：`animation.gif` 和 `frames/` 下至少 3 个关键帧。
- 报告文件：`generation-report.md`

## 功能原型选择

功能原型是执行设计前必须先找的参考基底，可以是：

- 用户提供的参考图。
- `功能截图/华为运动健康app` 或 `功能截图/华为穿戴` 中的整屏截图。
- `功能截图/华为穿戴/健康摘要与三叶草/swiper` 中的圆屏 Swiper 截图组。
- `运动健康App截图组件` 或 `穿戴截图组件` 中的组件组合。
- 组件索引中的页面类型、组件类型或状态记录。
- 两份设计规范中描述的页面类型和控件结构。

选择优先级：

1. 用户给的参考图。
2. 右侧竖向 Swiper、健康摘要或三叶草相关任务优先使用 `健康摘要与三叶草/swiper` 截图组。
3. 与目标场景最接近的功能截图。
4. 与页面结构最接近的 App 或穿戴组件索引条目。
5. 设计规范中的页面类型和控件规则。

如果找不到精确原型，输出“原型假设”，说明假设的页面类型、目标载体、组件组合和采用原因，然后继续设计。

引用功能截图或组件截图时，必须显式抽取与任务相关的细节，例如健康三环配色、心率时间轴格式、圆形列表 108% 缩放、竖向 Swiper 导航点点数和焦点尺寸。不要只写“参考官方截图”。

引用 `健康摘要与三叶草/swiper` 截图组时，至少抽取：466x466 圆屏画幅、右侧导航点点列位置、点半径、点距、蓝色焦点胶囊尺寸、焦点序列、与圆形弧边的内收距离、页面内容是否跟随切换。图生动图要把这些测量值写进 `generation-report.md`。

## 文生图

适用于用户只给文字需求，没有输入图片的任务。

执行步骤：

1. 解析需求：识别目标载体、场景、用户目标、输出比例、语言和关键数据。
2. 判定穿戴形态：如果目标是穿戴设备、手表、watch 或 wearable，且用户没有明确指定方形设备，按圆表/圆形屏寻找原型和生成界面。
3. 寻找功能原型：按“功能原型选择”规则找到最接近的原型图或组件组合。
4. 选择规范：手机 App 读取 `phone-health-app-design-constraints.md`；穿戴界面读取 `wearable-ux-guidelines.md`。
5. 选择组件：从组件索引中匹配导航、卡片、列表、图表、按钮、状态提示等。
6. 在原型基础上设计：保留原型的信息层级和组件节奏，按用户需求替换内容、数据和状态。
7. 输出提示词：包含功能原型、设计目标、布局、组件、数据、字体、颜色语义、系统壳层和负面约束。
8. 调用 `imagegen` 生成静态 PNG。
9. 将选定产物保存为 `outputs/<timestamp>-text-to-image-<slug>/final.png`。
10. 写入 `generation-report.md`，记录输入需求、原型、规范、最终提示词、产物路径和检查结果。

提示词模板：

```text
能力：文生图
功能原型：[原型路径或原型假设]
目标：为[用户目标]生成[目标载体]的[场景]界面。
设计规范：[手机运动健康 App 规范 / 智能穿戴规范]
布局：[安全区、对齐、导航、卡片/列表/图表层级]
组件：[使用的组件类型和状态]
数据：[指标、单位、数值、趋势或告警语义]
字体：HarmonyOS Sans / 鸿蒙字体
视觉：运动健康界面，清晰、克制、数据优先、状态明确
避免：[负面约束]
系统壳层：手机 App 禁止 iOS 状态栏、电量样式和 home indicator；穿戴界面保护设备安全区
输出：保存 PNG 到 outputs/<timestamp>-text-to-image-<slug>/final.png，并写入 generation-report.md
```

## 图生图

适用于用户提供参考图，并要求按规范改图、重绘或生成新版本。

执行步骤：

1. 拆解输入图：识别设备形态、页面类型、信息层级、组件、数据、颜色、状态和可读性问题。
2. 明确保留项：设备形态、输入图画幅比例、裁片边界、组件形态、可见元素、可见范围、布局骨架、关键组件位置、主数据、色彩气质或用户指定元素。
3. 明确修改项：新场景、新内容、新数据、新状态、组件替换、风格强弱或输出比例。
4. 选择规范：根据图中载体选择手机 App 或智能穿戴规范。
5. 按规范修正：安全区、字体、图标清晰度、触控热区、数据图表类型、导航和状态语义。
6. 输出提示词：包含“保留”“修改”“规范修正”“避免”四段；除非用户明确要求扩展画布，不要生成超宽页面或重构为新布局。参考图是局部裁片时，必须写明裁切关系、可见范围和信息密度，不得补全被裁掉的卡片下半部。
7. 先用 `view_image` 检查参考图是否可读，再调用 `imagegen` 进行编辑、重绘或参考生成。
8. 组件裁片默认保持参考图像素尺寸；若 `imagegen` 输出不同尺寸，使用 `python3 scripts/normalize_to_reference.py --input <generated.png> --reference <reference.png> --out <final.png>` 归一到参考图尺寸，并检查没有增加可见信息密度。
9. 将选定产物保存为 `outputs/<timestamp>-image-to-image-<slug>/final.png`；如扩展为完整页面，必须在 `generation-report.md` 记录允许扩展说明。
10. 写入 `generation-report.md`，记录参考图路径、拆解结果、保留项、修改项、提示词、产物路径、参考尺寸、输出尺寸和检查结果。

提示词模板：

```text
能力：图生图
输入图拆解：[设备形态、页面类型、层级、组件、数据、状态]
保留：[必须保留的输入图画幅比例、裁片边界、组件形态、可见元素、可见范围、结构、位置、主视觉或数据]
修改：[用户需求对应的新内容、新组件或新状态]
设计规范：[手机运动健康 App 规范 / 智能穿戴规范]
规范修正：[安全区、字体、图标、触控、图表、对齐、状态]
字体：HarmonyOS Sans / 鸿蒙字体
裁片约束：保持与输入图同等裁片关系；不得补全被裁掉的卡片下半部；不得为了展示新内容改变裁片内的信息密度
避免：改变设备形态、文字裁切、随机新增控件、噪声装饰、布局漂移、裁片内容补全
扩展说明：默认不扩展画布；若扩展为完整页面，必须说明原因
输出：保存 PNG 到 outputs/<timestamp>-image-to-image-<slug>/final.png，并写入 generation-report.md
```

## 文生动图

适用于用户给文字需求，要求生成动态界面、动效提示词或短视频提示词。

执行步骤：

1. 解析需求：确认目标载体、场景、时长、比例、动效目的、帧数和最终状态。
2. 判定穿戴形态：如果目标是穿戴设备、手表、watch 或 wearable，且用户没有明确指定方形设备，按圆表/圆形屏寻找原型、生成关键帧并验收。
3. 寻找功能原型：先找到静态界面原型，再推导可动元素。
4. 选择规范和组件：每一帧都必须符合对应设备/App 的安全区、组件和数据规则。
5. 拆解三类画面：首帧是起始状态，过程帧是交互或数据变化，尾帧是结果状态；3 帧只是最低关键状态；所有帧必须锁定同一页面类型。
6. 限定动效目的：只使用加载、切换、反馈、数据变化、告警或完成状态。
7. 输出动图提示词：包含首帧、过程帧、尾帧、页面类型锁定、锁定元素、运动元素、时长、帧数选择理由和负面约束；连续刷新、绘制或同步动效默认生成 8-12 帧。
8. 分别调用 `imagegen` 生成关键帧 PNG；曲线刷新类动画必须覆盖 `00:00 / 04:00 / 08:00 / 12:00 / 16:00 / 20:00 / 24:00` 等中间进度帧。
9. 合成前校验所有关键帧尺寸一致；若 `imagegen` 输出轻微尺寸差异，使用 `--normalize-to first` 归一化到首帧尺寸，或归一化到目标尺寸，并在报告中记录。
10. 使用 `python3 scripts/assemble_animation.py --frames <frames_dir> --out <output.gif> --duration 4 --normalize-to first` 合成 `animation.gif`。
11. 写入 `generation-report.md`，记录帧拆解、每帧提示词、GIF 路径、帧数、页面类型一致性、尺寸归一化和验收结果。

提示词模板：

```text
能力：文生动图
功能原型：[原型路径或原型假设]
目标：生成[时长]的[目标载体][场景]动图。
设计规范：[手机运动健康 App 规范 / 智能穿戴规范]
首帧：[起始页面、组件状态、关键数据]
过程帧：[动画过程、变化元素、反馈方式、节奏]
尾帧：[完成后的页面、结果状态、提示文案]
页面类型锁定：[所有帧保持同一页面类型；心率曲线任务保持同一心率趋势详情页]
锁定元素：[不移动或不变化的导航、设备框、主数据等]
运动元素：[图表、进度、按钮反馈、Toast、导航点、列表焦点等]
帧数：[最低 3 个关键状态；连续刷新/绘制/同步默认 8-12 帧，并说明选择理由]
字体：HarmonyOS Sans / 鸿蒙字体
避免：抖动、文字不可读、夸张动效、随机跳页、数据前后不一致、页面类型漂移、无关健康总览卡片
尺寸：所有关键帧同尺寸；必要时归一化到首帧或目标尺寸并记录
输出：保存关键帧到 outputs/<timestamp>-text-to-animation-<slug>/frames/，保存 GIF 到 animation.gif，并写入 generation-report.md
```

推荐动效：

- 加载/同步：进度变化、轻量旋转、同步中到完成。
- 运动训练：倒计时、定位中、开始/暂停反馈、关键指标轻微强调。
- 健康数据：折线绘制、范围高亮、告警强调、完成提示。
- 页面切换：横向或纵向 Swiper，导航点同步变化。
- 圆形穿戴列表：中心项放大到 108%，远离中心逐级缩小。

## 图生动图

适用于用户提供静态图，并要求让它动起来或生成动图版本。

执行步骤：

1. 拆解输入图场景：识别设备形态、页面类型、组件、数据、状态和视觉节奏。
2. 锁定参考图身份：保持输入图画幅比例、裁片边界、组件形态、可见元素、点数、焦点尺寸、边缘关系、屏幕形态、布局骨架、主数据、组件顺序和字体气质。小组件裁片要像素级几何锁定，不得重绘成新的组件规格。
3. 定义变化元素：图表、进度、导航、按钮反馈、Toast、告警、列表焦点或同步状态。
4. 拆解首帧、过程帧、尾帧：首帧等于输入图或合理起始态；过程帧表达动效；尾帧表达完成态；连续动效默认 8-12 帧；所有帧必须锁定同一页面类型或同一组件裁片类型。
5. 按规范修正：确保每一帧符合安全区、字体、图标、图表和状态语义。
6. 输出动图提示词：说明保留项、变化项、帧结构、时长、节奏、帧数选择理由和负面约束。
7. 先用 `view_image` 检查输入图，首帧保持输入图身份或生成规范修正后的首帧。
8. 如果参考图内容过弱，在 `generation-report.md` 标记“参考图内容弱/需补原型假设”，并锁定仍可见的白底、分隔线、列表行高、状态区位置等元素。
9. 对竖向 Swiper 导航点、小组件焦点移动等纯状态变化，不调用 `imagegen` 重绘每帧；先测量原图导航点中心、点半径、主焦点尺寸和紧贴导航点的清除框，再使用 `python3 scripts/render_swiper_focus_frames.py --input <reference.png> --out <frames_dir> --centers "x,y;x,y;..." --active-sequence "0,1,2,3,4,3,2,1" --clear-box x,y,w,h --dot-radius <r> --focus-size <w>x<h>` 从原图复制帧并只替换蓝色焦点状态。
10. 使用 `python3 scripts/verify_swiper_geometry.py --reference <reference.png> --frames <frames_dir> --clear-box x,y,w,h --expected-count <n>` 检查帧尺寸等于参考图，且清除框外像素不变；不通过就写失败报告。
11. 其他需要新增视觉内容的动效，调用 `imagegen` 生成过程帧和尾帧，必要时也生成修正首帧，统一保存到 `frames/`。
12. 合成前校验所有关键帧尺寸一致且等于参考图尺寸；若 `imagegen` 输出轻微尺寸差异，优先归一化到参考图尺寸或使用 `--normalize-to WIDTHxHEIGHT`，并在报告中记录。
13. 使用 `python3 scripts/assemble_animation.py --frames <frames_dir> --out <output.gif> --duration 4 --normalize-to none` 合成 `animation.gif`；若尺寸或几何检查失败，写失败报告，不进入合成。
14. 写入 `generation-report.md`，记录输入图、锁定元素、变化元素、每帧提示词或脚本参数、GIF 路径、帧数、页面类型一致性、尺寸归一化和验收结果。

提示词模板：

```text
能力：图生动图
输入图拆解：[设备形态、页面类型、组件、数据、状态]
锁定元素：[输入图画幅比例、裁片边界、组件形态、可见元素、点数、焦点尺寸、边缘关系、屏幕形态、布局骨架、主数据、组件顺序、关键视觉]
首帧：[输入图当前状态或修正后的起始状态]
过程帧：[具体动效、时长、节奏、变化元素]
尾帧：[完成状态、结果提示、最终数据或页面]
页面类型锁定：[所有帧保持同一页面类型或组件裁片类型]
小组件几何锁定：[如为竖向 Swiper 导航点，保留 5 个竖向导航点、主焦点尺寸、点距、点半径、弧边关系和组件尺度；只移动/替换蓝色焦点状态，不重新生成点半径、间距、弧线和裁片尺度]
确定性执行：[小组件焦点移动使用 scripts/render_swiper_focus_frames.py 复制原图生成帧，并用 scripts/verify_swiper_geometry.py 校验清除框外像素不变；如果无法测量点位或清除框，报告失败，不让 imagegen 重绘组件]
设计规范：[手机运动健康 App 规范 / 智能穿戴规范]
字体：HarmonyOS Sans / 鸿蒙字体
避免：界面扭曲、文字随机变化、布局漂移、闪烁、标签不可读
参考图信息：如果参考图内容弱，报告标记“参考图内容弱/需补原型假设”，并说明已锁定的可见元素
尺寸：所有关键帧同尺寸；必要时归一化到首帧或目标尺寸并记录
输出：保存关键帧到 outputs/<timestamp>-image-to-animation-<slug>/frames/，保存 GIF 到 animation.gif，并写入 generation-report.md
```

## 质量检查清单

完成前逐项检查：

- 是否明确四能力之一：文生图、图生图、文生动图、图生动图。
- 是否找到功能原型，或写明“原型假设”。
- 是否按目标载体选择手机 App 规范或智能穿戴规范。
- 穿戴设备、手表、watch 或 wearable 是否默认按圆表/圆形屏生成；只有明确出现“方表 / 方形屏 / 方形穿戴 / Watch Fit / rectangular watch / square watch”等方形设备信号时才允许方表。
- 未指定方表却生成方形表盘、方形屏或 Watch Fit 形态，应记为问题。
- 是否包含 HarmonyOS Sans / 鸿蒙字体。
- 圆形穿戴屏是否保护圆形安全区。
- 圆形屏图表坐标轴、时间轴、右侧纵轴、导航点、底部控件和边缘列表项是否明显内收。
- 心率趋势时间轴是否显示 `00:00 / 12:00 / 24:00`，且未使用 `0点 / 24点`。
- 方形穿戴屏和手机 App 是否有合理对齐、导航、卡片、列表和图表层级。
- 手机 App 是否禁止 iOS 状态栏、电量样式和 home indicator，并使用 HarmonyOS 风格或弱化系统壳层。
- 组件裁片是否避免新增手机状态栏；若参考图含状态栏，是否使用 HarmonyOS 风格或弱化系统壳层，没有通用手机/iOS 化状态栏。
- 健康首页三环是否使用外圈暖橙/红橙、中圈黄色/暖色、内圈浅蓝/青蓝的参考关系。
- 数据图表是否匹配数据类型：进度、占比、范围、线形、柱状或状态反馈。
- 图生图和图生动图是否写清保留项与修改项，并锁定输入图画幅比例、裁片边界、组件形态、可见元素、可见范围和信息密度。
- 局部组件裁片是否保持同等裁切关系，没有补全被裁掉的卡片下半部，没有为了展示新内容增加裁片内的信息密度。
- 图生动图的小组件裁片是否像素级几何锁定；竖向 Swiper 是否保留点数、主焦点尺寸、点距、点半径、弧边关系和组件尺度，只改变蓝色焦点位置。
- 竖向 Swiper 小组件是否使用确定性脚本从原图复制帧；如果使用 `imagegen` 结果，是否已裁切/缩放回参考图尺寸并通过点位检查。
- 动图是否包含首帧、过程帧、尾帧、锁定元素和运动元素；连续动效是否达到 8-12 帧或说明了帧数理由。
- 动图所有帧是否保持页面类型一致性，没有从心率趋势详情页漂移到健康总览页或其他页面模块。
- 动图所有关键帧是否同尺寸；如归一化，是否记录归一化目标和原因。
- 是否已调用 `imagegen` 生成 PNG，或在失败报告中明确说明不可用并降级为提示词。
- 是否没有使用本地绘图、截图拼接、空白占位图或仅提示词冒充 `imagegen` 生图产物。
- 静态图是否保存为 `final.png`；动画是否保存为 `animation.gif` 且 `frames/` 至少有 3 个关键帧。
- `generation-report.md` 是否记录能力、输入、工具、提示词、产物路径和失败/降级情况。
- 负面约束是否避免文字裁切、设备变形、随机控件、不可读微字、过度装饰和伪称官方。

## 迭代方式

从测试对话导入失败案例时：

1. 先归类失败属于原型选择、规范应用、组件选择、图片拆解、动效拆帧或提示词表达。
2. 只补最小必要规则，不做无关重写。
3. 重新运行 skill 校验和关键词检查。
4. 说明新增规则会防止哪类失败再次出现。
