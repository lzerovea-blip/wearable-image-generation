## 核心口径

该指南是智能穿戴设备的专项 UX 标准。做运动健康穿戴界面拆解、重绘、图生图提示词或控件素材归档时，应同时考虑通用应用体验标准、通用设计基础、控件、人机交互、系统能力和“针对多设备设计/智能穿戴”章节中适用于智能穿戴的部分。

素材库中涉及 App 或穿戴设备界面生成时，字体统一使用鸿蒙字体。

## 跨章节穿戴设计约束

### 1. 设备与场景

- 穿戴设备是贴身辅助设备，核心场景集中在生活提醒、运动、健康监测与腕上装饰。
- 运动健康类穿戴界面应突出“短时可读、轻量操作、即时反馈”，不把手机端完整流程照搬到小屏。
- 充分利用设备特性：心率、血氧、GPS、陀螺仪、加速计、表冠、按键、语音与腕上佩戴状态。
- 通知要克制，避免重复、无效或高频打扰；运动/健康异常提醒需要明确优先级和可读性。

### 2. 应用架构

- 非空界面一般采用“标题栏 + 内容区”，让用户明确当前应用或层级。
- 有新增、添加等强操作时，可在顶部使用圆形按钮，必要时支持悬浮。
- 空状态分两类：可操作空状态用“按钮 + 文字说明”；无操作空状态用“图标 + 文字说明”。
- 首页可采用“多功能菜单为首页”或“主功能为首页”。运动健康场景中，主线功能如运动中、健康概览、训练记录可作为首页主内容，次级功能通过右滑/菜单进入。
- 平级内容超过一屏时，不要在圆形屏边缘硬塞信息；优先使用横向切屏、垂直切屏或垂直平铺。

### 3. 人机交互

- 表冠交互应通用、易操作、响应及时；反馈可通过表盘、语音提醒或界面刷新体现。
- 运动功能是表冠交互的特殊场景：上表冠短按可能进入运动暂停/启动界面，设计自定义交互时不能与此冲突。
- 触屏基础手势可用于点击、长按、滑动、捏合；拖拽、双击、旋转等在穿戴端需谨慎使用。
- 自定义手势不能成为唯一完成路径；健康、运动关键流程必须有可发现的显性控件。

### 4. 间距与版式

- 圆形屏：左右 26vp、顶部 20vp、底部 6vp；长页面底部滚动余量 40vp；文本优先居中。
- 圆形穿戴屏产物必须保留 PNG alpha 通道；圆外区域透明、四角 alpha=0，不交付黑色方形底图包住圆屏。
- 方形屏：左右顶部 12vp、底部 6vp；长页面底部滚动余量 36vp；文本优先左对齐。
- 设备形态未明确时使用圆形屏规则，不主动切换为方形屏或 Watch Fit 形态。
- 圆形屏弹出框、控件和文本间距应单独检查，避免内容贴边或被弧形边缘裁切。
- 长列表、健康指标列表、运动模式列表应关注焦点、层级和滚动状态；圆形屏多列表项场景用中心项放大规则。

### 5. 控件约束

- 导航点：平级分页内容需要显示数量和当前位置；横向内容配横向点，纵向内容配竖向点。
- 方形屏导航点：竖向点宽 5vp、间隔 4vp、主焦点长 14vp、边距 2vp；横向点高 5vp、间隔 4vp、主焦点长 10vp、边距 6vp。
- 列表：同组列表保持一致的间距、对齐和层级；右侧操作和主信息应分区明确。
- 按钮：按重要性选择强调按钮、填充按钮、文字按钮；运动中暂停/结束/继续等操作需要状态清楚。
- 进度与数据可视化：运动进度、健康范围、占比数据要按数据结构选择进度形、占比形、范围形或线形，不用颜色制造误导。
- Toast/即时反馈：文本短、可读，不包含按钮或链接；避免短时间连续弹出，单次时长不超过 3 秒。
- 弹出框：只用于必须关注或必须确认的场景，内容区应说明影响、范围或下一步。

### 6. 图标与字体

- 穿戴应用图标：圆形、单层、152px x 152px、PNG、1px 内间距。
- 界面图标：推荐不小于 20vp，必须不小于 16vp，且不能模糊、压缩或锯齿。
- 字体统一使用鸿蒙字体；穿戴端文本推荐不小于 13vp，最小不得小于 10vp。
- 字体层级要少而清晰，避免在小屏上用过多字号、颜色和字重制造复杂度。

## 设计检查要点

### 1. 界面布局

- 圆形屏优先检查内容是否避开屏幕弧形边缘，关键文字、按钮和数据指标不得被截断。
- 圆形屏产物检查圆外背景：最终 PNG 需要带 alpha 通道，圆外区域透明，四个角的 alpha 值为 0；若无用户明确例外，圆外黑色实底应记为问题。
- 圆形屏图表坐标轴、时间轴、右侧纵轴、导航点、底部控件和边缘列表项必须明显内收，避开圆形弧边。
- 心率曲线页右侧纵轴刻度与曲线终点必须整体向屏内内收，距离圆形弧边留出明显安全区。
- 心率趋势时间轴必须显示 `00:00 / 12:00 / 24:00`，禁止用 `0点 / 24点` 替代。
- 方形屏优先检查左右与顶部基础边距，信息密度可略高，但底部操作区仍需留出安全空间。
- 长页面需要单独检查滚动到底部后的底部留白，避免最后一个项目贴边或难以点击。
- 圆形屏文本以居中更稳定；方形屏文本以左对齐更利于阅读和列表浏览。

### 2. 导航点

- 多个子页面或子类别使用 Swiper 导航点表达位置和数量。
- 横向滑动页面使用横向导航点，纵向滑动页面使用竖向导航点。
- 导航点数量应与页面数量一致。
- 切换页面时主焦点需要同步变化，不能出现点位不更新、数量不一致或方向错误。
- 竖向 Swiper 导航点需保持点数、方向、主焦点尺寸和完整显示；整体向屏内轻微内收，避免贴近圆形屏弧边或设备边框。
- 图生动图的小组件裁片必须像素级几何锁定；如输入图包含 5 个竖向导航点，所有帧都保留 5 个竖向导航点、主焦点尺寸、点距、点半径、弧边关系和组件尺度，只移动/替换蓝色焦点状态，不重新生成点半径、间距、弧线和裁片尺度。
- 右侧竖向 Swiper 可参考 `功能截图/华为穿戴/健康摘要与三叶草/swiper`：蓝色焦点是贴着右侧点列移动的竖向胶囊，普通点保持圆点形态，点列整体沿圆形弧边内收并保持稳定。

### 3. 圆形屏列表缩放

- 圆形屏长列表不应只是等比例平铺，应通过中心项放大来增强当前焦点。
- 中心项固定为约 108% 的轻微放大是检查重点，不能放大成大卡片或占据屏幕主体。
- 离中心越远，列表项应越小，形成连续缩放关系。
- 运动模式列表、健康指标列表、设备菜单列表都适合用该规则检查。

### 4. 应用图标

- 穿戴端 icon 应按圆形图标检查，不能沿用未适配的手机端方形或分层图标。
- 图标需要保留 1px 内间距，避免边缘被裁切。
- 输出素材时应记录 152px x 152px 的设计尺寸。
- 检查应用列表与消息通知两类场景，确保无模糊、变形、压缩、锯齿和裁切。
